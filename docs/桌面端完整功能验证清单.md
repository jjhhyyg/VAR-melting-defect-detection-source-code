## 3. 当前未验证项

下面这些不是“锦上添花”，而是你要声称“完整功能验证完成”之前必须面对的空白。

### 3.1 必须补测

#### A. 导出与结果交付

- [ ] HTML 报告实际导出落盘
  - 验收标准：能选择导出路径，生成 `.html` 文件，可在本机浏览器正常打开
- [ ] PDF 报告实际导出落盘
  - 验收标准：能选择导出路径，生成 `.pdf` 文件，内容与报告预览一致
- [ ] 结果页中的“查看结果”完整链路
  - 验收标准：任务卡片跳转、详情加载、图表和统计卡片均正常

#### B. 主流程配置矩阵

- [ ] `启用预处理=关`
  - 验收标准：任务可直接分析成功，不依赖预处理文件
- [ ] `启用预处理=开` 且 `预处理强度=轻度`
  - 验收标准：任务完成，预处理视频可落盘
- [ ] `启用预处理=开` 且 `预处理强度=强度`
  - 验收标准：任务完成，预处理视频可落盘
- [ ] `熔池增强=开`
  - 验收标准：任务完成，结果页与报告页正常
- [ ] `追踪轨迹合并=开`
  - 验收标准：任务完成，无 worker 崩溃，无结果页异常
- [ ] `追踪轨迹合并` 各策略
  - 验收标准：至少每个策略能完整跑通一条任务

#### C. 真实业务能力

- [ ] 真实业务视频下的异常事件生成
  - 验收标准：`anomaly_events` 非空，结果页事件列表和时间轴有内容
- [ ] 真实业务视频下的追踪物体生成
  - 验收标准：`tracking_objects` 非空，详情页统计与数据库一致
- [ ] 真实业务视频下的结果视频标注正确性抽查
  - 验收标准：结果视频中的标注与 `tracking.json` 至少抽样一致

#### D. 任务生命周期

- [ ] 删除任务
  - 验收标准：数据库记录删除，任务目录清理，UI 卡片消失
- [ ] 重新分析
  - 验收标准：旧结果被清空或替换，任务重新进入执行并可完成
- [ ] 多任务排队
  - 验收标准：创建多个任务后按顺序执行，无状态串扰
- [ ] 重启恢复策略
  - 验收标准：App 在任务等待中 / 执行中重启后，状态符合预期，不出现伪“分析中”
- [ ] 超时路径
  - 验收标准：能稳定进入 `COMPLETED_TIMEOUT`，而不是卡死或误判为 `FAILED`

#### E. 错误路径

- [ ] 非法文件类型
  - 验收标准：桌面端明确拒绝，错误信息可读
- [ ] 损坏视频文件
  - 验收标准：任务失败，错误原因清晰，不残留假完成状态
- [ ] 缺失 `ffmpeg` / `ffprobe`
  - 验收标准：任务失败，错误信息直接指向外部依赖缺失
- [ ] worker 异常退出
  - 验收标准：数据库和 UI 一致写成 `FAILED`
- [ ] 磁盘空间不足
  - 验收标准：任务失败且提示明确，不产生半成品假结果

#### F. Windows CUDA Runtime 双包流程

- [ ] Windows 主安装包不内置完整 CUDA runtime
  - 验收标准：`npm run desktop:windows:build` 可生成 NSIS 安装包，安装包不包含 5GB+ `runtime/windows-x64`
- [ ] Windows runtime zip 生成
  - 验收标准：`npm run desktop:windows:runtime` 生成 `VAR-Desktop-CUDA-Runtime-windows-x64-<version>.zip`，zip 根目录包含 `runtime-manifest.json`
- [ ] 首次启动强制导入算法包
  - 验收标准：未导入 runtime 时不能进入主程序，只能选择算法包 zip 或重新检查
- [ ] 错误算法包导入失败
  - 验收标准：平台不匹配、版本不匹配、损坏 zip、缺失文件均给出可读错误
- [ ] 正确算法包导入成功
  - 验收标准：导入后通过 `desktop_worker.exe --self-check`、`ffmpeg.exe -version`、`ffprobe.exe -version`，并进入主程序
- [ ] 升级后强制导入新 runtime
  - 验收标准：App version 与 runtime build id 不一致时不能继续使用；导入新 runtime 成功后旧 runtime 被删除
- [ ] Windows CUDA 完整分析
  - 验收标准：导入算法包后至少跑通一条真实或代表性视频分析任务，并确认使用 CUDA 版 worker

## 6. 完整功能验证通过的最低标准

只有同时满足下面条件，才可以说“桌面端完整功能验证完成”：

1. `3.1 必须补测` 全部通过。
2. 至少有一组真实业务视频样本成功生成异常事件或追踪物体，而不是只有合成空场景。
3. HTML / PDF 报告均完成实际导出落盘验证。
4. 删除、重新分析、多任务排队、重启恢复四类任务生命周期场景全部通过。
5. 不再出现“数据库已完成 / 已失败，但 UI 仍显示分析中”的状态不一致问题。
